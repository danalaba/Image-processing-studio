# Зафіксовані перевірки

Стан на **2 листопада 2026 року**. Програмний код: коміт `eb590a6`, версія API
`0.5.0`. Матеріали захисту додаються окремим комітом без зміни роботи застосунку.
Автоматичні перевірки виконувалися в керованому середовищі Linux/Docker.

| Перевірка | Фактичний результат | Як повторити |
|---|---|---|
| PostgreSQL/API suite | 59 тестів, OK | Команда в README; окрема БД `studio_test` |
| Синтаксис Nginx | `nginx -t`: successful | `docker compose exec nginx nginx -t` |
| HTTP-балансування | У зафіксованому прогоні 6 відповідей api-1 та 6 api-2 | `scripts/check_load_balancing.py` |
| Спільний стан API | Сесія, метадані й однакові PNG-байти доступні через обидва API | Той самий HTTP-скрипт |
| Ізоляція й logout | Чужий результат — 404; відкликаний токен — 401 на обох API | Той самий HTTP-скрипт |
| Workers | Два пакетні jobs завершилися на двох різних worker ID | `scripts/check_queue.py --batch --require-two-workers` |
| ZIP | Валідні архіви, PNG усередині мають очікувані розміри | Queue-скрипт, batch-тести |
| Браузер | Реєстрація, 3-файловий вибір, ZIP, повторний вхід/історія, скасування, мобільна верстка; без JS-помилок | Ручний сценарій у DEFENSE.md |
| Зупинка api-2 | Health, створення job і завантаження працювали через api-1 | Ручний сценарій відмови API |

| Ліміти між API | Три одночасні запити при зупинених workers дали 202, 202, 429 та рівно два jobs | Контрольований fault-сценарій у хмарному середовищі |
| Вхідний ліміт Nginx | Завеликий Content-Length отримав 413 до API | Контрольований HTTP fault-сценарій |

Це результати вже виконаних перевірок, а не прогноз результатів на іншому Mac.
Під час власного показу використовуйте актуальний вивід: UUID та Docker hostnames
змінюються, співвідношення відповідей API може відрізнятися від 6/6.

Поломки усувалися до підтвердження готовності. Зокрема, локальний healthcheck
Nginx у хмарі спершу отримував 403 через успадкований HTTP-проксі. Після перевірки
причини для loopback-healthcheck додано `wget -Y off`, і він став healthy.
Зовнішня TLS-перевірка під час Docker-збірок залишалася увімкненою.

## Як читати докази

- 59 тестів підтверджують поведінку коду на PostgreSQL, але самі по собі не
  доводять роботу Nginx чи реального брокера: publish у них підмінений.
- HTTP-скрипт доводить відповіді двох API та спільний стан за одним Nginx.
- Queue-скрипт доводить виконання різних jobs двома реальними workers.
- Docker `running`, відкритий порт або один скриншот 100% не є достатнім доказом
  усіх цих властивостей разом.
- Зупинка одного API не є перевіркою відмови Nginx, PostgreSQL чи Redis; повну
  високу доступність і вимірювання максимальної продуктивності тут не заявлено.

Дивіться [сценарій показу](DEFENSE.md), [команди](COMMANDS.md) та
[повний README](../README.md). Для документаційного оновлення ці перевірки не
запускалися повторно: робочий код і конфігурація сервісів не змінювалися.
